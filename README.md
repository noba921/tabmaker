# TAB Maker

![Python](https://img.shields.io/badge/python-3.10--3.12-blue)
![License](https://img.shields.io/badge/license-MIT-green)
![Platform](https://img.shields.io/badge/platform-Windows-lightgrey)

YouTubeのURL(または手持ちの音声ファイル)を読み込むと、AIが**楽器ごとに音を分離**し、
**ギター/ベースのTAB譜・ドラム譜・メロディの五線譜・コード進行**を自動生成する
ローカルアプリです。MusicXML と MIDI で書き出せるので、MuseScore や Guitar Pro で
清書・編集できます。

すべてローカルPCで動作し、音源が外部サーバーに送られることはありません。

```
YouTube URL ──► 音源取得 ──► パート分離 ──► 拍・小節の推定 ──► 採譜 ──► 運指の最適化
                                                                              │
                                    ブラウザで表示 ◄── MusicXML / MIDI ◄───────┘
```

## できること

- **曲を探す** — 曲名で検索して、候補から選んで採譜を開始
- **音源だけ取り込む** — 採譜せず、WAV/FLAC/MP3 でそのまま保存(数十秒で終わる)
- **5パートを同時に採譜** — メロディ / ギター / ベース / ピアノ / ドラム
- **コード進行の表示** — 譜面の上にコードネームを並べる
- **自分の楽器に合わせる** — チューニング・カポ・使用フレット範囲を変えて運指を再計算
- **再生と同期** — 音源を鳴らしながら譜面上の再生位置を追う
- **エンジンの切り替え** — 各処理段のアルゴリズムを画面から選択(GPU向けの選択肢も同梱)

## セットアップ (初回のみ)

0. **重要**: このフォルダを `C:\tabmaker` など浅い場所にコピーしてから始める
   (深いフォルダだとWindowsのパス長制限でPyTorchが動きません)
1. Python 3.10〜3.12 をインストール(未導入なら https://www.python.org/ )
2. `setup.bat` をダブルクリック(PyTorch等で数GBダウンロードするので時間がかかります)
3. 終わったら `selftest.bat` で動作確認(合成音源で採譜〜楽譜出力まで一通り試します)

`setup.bat` は本体に加えて次の3つを入れようとします。どれも失敗しても本体は動きます
(その処理だけ内蔵の簡易版に切り替わります)。

| 追加されるもの | 何が良くなるか | 失敗しやすい条件 |
|---|---|---|
| basic-pitch | 和音を含む音符推定 | onnx/TFのビルド環境 |
| Beat This! | 小節の頭を外さなくなる・拍子の自動判定 | ほぼ失敗しない |
| ADTOF-pytorch | ドラムの種類の聞き分け | **Gitが未インストールだとスキップ** |

### GPUを買ったら

`setup-gpu.bat` を実行すると、PyTorchをCUDA版に入れ替えて RoFormer 系の分離モデルを追加します。
そのあとアプリの「処理エンジンの設定」でGPU向けエンジンに切り替えてください。
**CPUのままでも全機能が動くので、急いで実行する必要はありません。**

## 使い方

1. `run.bat` をダブルクリック → ブラウザで `http://127.0.0.1:8766` が開く
2. YouTubeのURLを貼る(またはmp3/wav等のファイルを読み込む)
3. 処理が終わると譜面画面へ。上のタブでパートを切り替える

処理は5段階で、1曲あたり **数分〜十数分**(CPUの場合)。初回はAIモデルのDLが入ります。

## 画面でできること

- **パート切り替え** — メロディ / ギター / ベース / ピアノ / ドラム
- **コードネーム表示** — 譜面の上にコード進行が並ぶ。MusicXMLにも書き出される
- **再生** — 全体ミックス、またはそのパートだけの音を鳴らせる。譜面上を赤い線が走る
- **チューニング・カポ・最高フレット** — 変えて「運指を作り直す」で押さえ方を再計算
- **小節の頭を1拍ずらす** — 小節線が半端な位置に来たときの手直し用
- **ダウンロード** — MusicXML / MIDI / テキストTAB
- **処理エンジンの設定**(トップ画面の下) — 各処理段で使うモデルを選べる

## 音源だけ取り込む(採譜しない)

画面上部の「取り込み方」を **音源だけ保存** に切り替えると、分離も採譜もせず、
音声ファイルとして保存するだけになります。検索結果からもURL入力からも使えます。

| 形式 | 用途 |
|---|---|
| **WAV 44.1kHz ステレオ**(既定) | 音色を扱う解析。非可逆圧縮のノイズが入らない |
| WAV 44.1kHz モノラル | 学習データ用。容量が半分 |
| FLAC 44.1kHz | 可逆圧縮。容量を抑えつつ音は劣化しない |
| MP3 320kbps | 共有用。**音色の分析には不向き** |

保存先は `C:\tabmaker\audio` です。他のアプリからはこのパスで直接読めます。
画面の「保存した音源」から一覧・ダウンロード・削除ができます。

> 音色を見る用途(エフェクターやアンプの判別など)で使う場合、MP3は避けてください。
> 非可逆圧縮は高域を間引くため、歪みの質感が元の音と変わってしまいます。

## 処理エンジンの切り替え

5つの処理段それぞれに複数のバックエンドがあり、画面から切り替えられます。
設定は `config.json` に保存され、**次に採譜する曲から反映**されます。
「おまかせ」にしておくと、インストール済みのものの中から一番良いものが自動で選ばれます。

| 処理段 | 選べるエンジン |
|---|---|
| パート分離 | **Demucs 6stem**(既定・ギター/ピアノを分離) / Demucs 4stem(最速) / Demucs 微調整版(低速) / **RoFormer+Demucs 6stem**(GPU) |
| 拍・小節 | **Beat This!**(既定) / librosa(内蔵) |
| 音符推定 | **basic-pitch**(既定) / librosa pyin(軽量) / 外部スクリプト(GPU) |
| ドラム | **ADTOF**(既定) / 内蔵ヒューリスティック |
| コード進行 | 内蔵(既定) / なし |

未インストールのエンジンは選択肢がグレーになり、導入方法が表示されます。
選んだエンジンが実行時に失敗した場合も、自動で軽い方に切り替えて処理を続けます。

### 外部の採譜モデルを繋ぐ

音符推定で「外部スクリプト」を選ぶと、`config.json` の `pitch_external_cmd` に書いた
コマンドを呼び、出力されたMIDIを読み込みます。YourMT3+ のような pip で入らない
研究用モデルを繋ぐための拡張点です。

```json
"pitch_external_cmd": "python C:/YourMT3/transcribe.py --audio {input} --output {output}"
```

`{input}` に分離済みステムのwav、`{output}` に書き出し先のMIDIパスが入ります。

## 出力ファイル

| 形式 | 用途 |
|---|---|
| MusicXML | MuseScore・Guitar Pro・Dorico などで開いて清書・編集。**これが本命** |
| MIDI | DAWに取り込む。打ち込みの叩き台に |
| テキストTAB | `e|--3--5--|` 形式。メモやチャットに貼れる |

## 仕組み

1. **音源取得** — yt-dlp でダウンロード → ffmpegでWAV化
2. **パート分離** — Demucs 6stem で vocals / drums / bass / **guitar** / **piano** / other に分ける
3. **拍・小節の解析** — Beat This! が拍と小節の頭を同時に出す。拍子も自動判定
4. **採譜** — basic-pitch で音符化。ドラムは ADTOF(学習済みモデル)で5クラスに分類し、
   強弱は分離ステムのA特性重み付けRMSから推定
5. **コード認識** — ドラム以外を足した音のクロマ特徴 + ビタビ探索で進行を推定
6. **運指の最適化** — 同じ音でも押さえ方は複数あるので、動的計画法で
   左手の移動が最小になる弦・フレットの組み合わせを選ぶ

## 精度について(正直なところ)

自動採譜は完璧ではありません。**大枠を取ってからMuseScoreで直す**のが現実的な使い方です。

- **ベース**は単音主体なので一番当たります
- **コード進行**は音符レベルの採譜より安定します。TAB譜が荒くてもコードが合っていれば
  曲はコピーできるので、まずここを見るのがおすすめです
- **ドラム**はキック・スネア・ハイハットはよく当たります。ADTOFが入っていない場合は
  内蔵の簡易判定になり、タムとスネアの取り違えが起きやすくなります
- **ギター/ピアノ**は6stem分離のおかげで他の楽器の混入は減りましたが、
  ピアノステムの品質は Demucs 側でも発展途上です。4stemに切り替えた場合は
  両方とも "other" から採譜するため、シンセや弦楽器が混ざります
- **メロディ**はしゃくり・ビブラートが半音に丸められます
- 小節の頭がずれることがあります → 画面の「小節の頭 ◀ 1拍 / 1拍 ▶」で直せます
- テンポが途中で変わる曲、ルバートの効いた曲は苦手です

## コツ・注意

- **NVIDIA GPUがあると劇的に速くなります**(CUDA版PyTorchを入れる)
- 音数が少なくミックスがすっきりした曲ほど精度が上がります
- 曲データは `songs/` に保存されます(削除はアプリ内から)
- 容量が気になる場合は、設定で「音源の保存 → ミックスのみ」にすると1曲2〜3MBまで落ちます
- 使わないパートのチェックを外すと、その分だけ採譜が速く終わります

## トラブルシューティング

- **まず `check.bat`** → Python/ライブラリ/ffmpeg/ポートを診断します
- **`selftest.bat`** → 採譜〜楽譜出力の処理そのものが壊れていないか確認します(57項目)
- **`apitest.bat`** → サーバーのAPI・保存形式・設定まわりを確認します
- 「このサイトにアクセスできません」→ run.batの黒い画面に `TAB Maker` と出てから F5
- サーバーが落ちる → エラーは `server.log` に記録されます
- Pythonは **3.10〜3.12推奨**。3.13以降だと librosa/demucs が入らないことがあります
- **`ImportError: ... compiled using NumPy 2.x cannot be run in NumPy 1.x`**
  → basic-pitch が連れてくる TensorFlow が numpy を1系に固定する一方で、
  numpy 2系向けの scipy が入っている状態です。次で直ります:
  ```
  cd C:\tabmaker
  venv\Scripts\python.exe -m pip install --force-reinstall "numpy<2" "scipy<1.14"
  ```
- **エンジンが「未導入」と出る** → `check.bat` を実行すると、パッケージごとに
  読み込めない理由(実際の例外メッセージ)が表示されます。
  インストールはできているのに読み込めない場合は、たいてい上のnumpy/scipy問題です
- YouTube読み込み失敗 → `update-ytdlp.bat` で yt-dlp を更新
- おうちカラオケと同時に起動できます(ポートが 8765 / 8766 で別のため)
