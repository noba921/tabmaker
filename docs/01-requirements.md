---

## 1. 背景と目的

### 1.1 背景

ギターやベースで好きな曲をコピーしようとすると、まず譜面を探すことになる。しかし

- 市販のバンドスコアは出版されている曲が限られ、1曲あたりの単価も高い
- ネット上のTAB譜は玉石混交で、そもそも存在しない曲が多い
- 耳コピは時間がかかり、初中級者には難度が高い

という問題がある。一方で、音源分離(Demucs等)と自動採譜(basic-pitch等)の技術は
個人のPCで動く水準まで来ている。

### 1.2 目的

**YouTubeのURLまたは手持ちの音声ファイルから、楽器ごとのTAB譜・楽譜を自動生成し、
MuseScore等で清書できる形式で出力する**ローカルアプリケーションを構築する。

完全な採譜精度は目指さない。**「耳コピの下書きを自動で作る」**ことを目的とし、
最終的な清書は利用者がMusicXMLを編集して行う前提とする。

### 1.3 スコープ外

- 商用配布、他人への譜面の販売・再配布
- リアルタイム採譜(演奏しながらの採譜)
- 譜面のアプリ内での本格的な編集(音符の追加・削除)
- サーバー上での動作(ローカル実行専用)

## 2. 利用者と利用シーン

### 2.1 想定利用者

| 属性 | 内容 |
|---|---|
| 主利用者 | 開発者本人(趣味でギターを弾く学生) |
| 技術レベル | Pythonが読める。コマンドラインに抵抗はないが、日常操作はGUIを好む |
| 実行環境 | Windows ノートPC(GPUなし)。将来的にGPU搭載機に移行する可能性がある |
| 副次利用者 | 同様の目的を持つ第三者(GitHubで公開するため) |

### 2.2 主要な利用シーン

1. **曲を探して採譜する** — 曲名で検索し、候補から選んで採譜を開始する
2. **TAB譜を見ながら練習する** — 音源を再生しながら、譜面上の再生位置を追う
3. **自分の楽器に合わせる** — チューニングやカポを変えて運指を作り直す
4. **清書する** — MusicXMLをMuseScoreで開いて手直しする

| ID | 機能 | 優先度 | 概要 |
|---|---|---|---|
| F-01 | YouTube検索 | 中 | 曲名・アーティスト名で検索し、候補を一覧表示する |

| F-07 | ドラム採譜 | 中 | 打点を検出し、打楽器の種類と強弱を推定する |

| F-12 | 運指の再計算 | 中 | チューニング・カポ・使用フレット範囲を変えて作り直す |
| F-13 | 小節位置の補正 | 中 | 小節頭の推定がずれた場合に手動で補正する |
| F-14 | 譜面の書き出し | **高** | MusicXML / MIDI / テキストTAB を出力する |
| F-15 | エンジンの切り替え | 中 | 各処理段で使うアルゴリズムを選択する |

| F-17 | 環境診断 | 低 | 依存関係の状態を確認し、問題の原因を表示する |

### 3.2 機能詳細

#### F-01 YouTube検索
- 入力: 検索語(曲名、アーティスト名等)
- 出力: 最大40件の候補(サムネイル・タイトル・チャンネル名・尺・再生回数)
- 取得済みの曲には「取込済」の印を付ける
- 一覧情報のみ取得し、動画1本ずつの詳細解析は行わない(数秒で応答すること)

#### F-04 パート分離
- 既定は6ステム(vocals / drums / bass / guitar / piano / other)
- 選択したモデルが guitar / piano を出力しない場合、それらのパートは other から採譜する
- 分離エンジンが実行時に失敗した場合、より軽いエンジンにフォールバックして処理を継続する

#### F-05 拍・小節の推定
- テンポ(BPM)、拍の時刻列、小節頭の位置、1小節あたりの拍数を求める
- 拍位置は等間隔とは限らない(テンポ変動を時刻列として保持する)

#### F-06 音符の推定
- 出力する音符は「開始拍・長さ(拍)・音高(MIDIノート番号)・強さ」を持つ
- 発音位置は16分音符グリッドに量子化する
- ベース・メロディは単音として扱い、重なりを解消する
- ギター・ピアノは同時発音を最大6音までに制限する

#### F-09 運指の最適化
- 対応チューニング: ギター5種、ベース4種(§付録A)
- カポ(0〜9フレット)、使用する最高フレット(12〜22)を指定できる
- 音域外の音はオクターブ単位で移動して収める
- 同時に鳴る音に同じ弦を割り当ててはならない
- 弦とフレットから元の音高が復元できること(**必須制約**)

#### F-14 譜面の書き出し
| 形式 | 内容 |
|---|---|
| MusicXML | TAB譜(弦・フレット情報つき)、五線譜、打楽器譜、コードネーム、調号、テンポ |
| MIDI | フォーマット1。パートごとにトラックを分け、ドラムはチャンネル10 |
| テキストTAB | `e|--3--5--|` 形式のASCII |

## 4. 非機能要件

### 4.1 性能

| ID | 項目 | 目標 |
|---|---|---|
| N-01 | 採譜時間(CPU) | 4分の曲で15分以内(全パート・既定エンジン) |
| N-02 | 採譜時間(パート限定) | ベース+ドラムのみなら上記の半分程度 |
| N-03 | 検索の応答 | 5秒以内 |
| N-04 | 譜面表示 | 曲を開いてから1秒以内に描画 |
| N-05 | ディスク使用量 | 4分の曲で1曲あたり15MB以内(既定設定) |

### 4.2 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10/11(他OSでもPythonが動けば可) |
| Python | 3.10〜3.12 |
| メモリ | 8GB以上 |
| ディスク | 初期セットアップに約5GB(PyTorch等)+ 曲データ |
| GPU | 不要。あれば高品質エンジンを選択できる |
| ブラウザ | Chrome / Edge / Firefox の最新版 |
| ネットワーク | 音源取得・モデルDL時のみ必要 |

### 4.3 信頼性

- **R-01**: いずれかのエンジンが失敗しても、より軽い実装にフォールバックして処理を続けること
- **R-02**: 処理が失敗した場合、中途半端なデータを残さず、原因を画面に表示すること
- **R-03**: サーバーの例外はすべてログファイルに記録すること
- **R-04**: 依存ライブラリの不整合を診断ツールで検出し、修復手順を提示すること

### 4.4 保守性

- **M-01**: 各処理段(分離・拍・採譜・ドラム・コード)は差し替え可能な単位に分離すること
- **M-02**: 新しいアルゴリズムを追加する際、登録情報の追記と関数1つの実装で済むこと
- **M-03**: 外部モデルを呼ぶ拡張点を用意し、pipで入らない研究用モデルも接続できること
- **M-04**: 自動テストにより、主要な処理の正しさを機械的に検証できること

### 4.5 使用性

- **U-01**: セットアップはバッチファイルのダブルクリックで完結すること
- **U-02**: 処理の進捗を段階ごとに表示すること
- **U-03**: 自動推定が外れやすい箇所(小節頭)には手動補正の手段を用意すること
- **U-04**: 各パートの精度の限界を画面上に明示すること

## 5. 制約事項

### 5.1 技術的制約

| ID | 制約 | 理由 |
|---|---|---|
| C-01 | インストール先のパスは80文字以内 | Windowsのパス長制限でPyTorchのDLL読み込みが失敗する |
| C-02 | numpy は 1系に固定 | basic-pitchが導入するTensorFlow 2.15がnumpy<2を要求し、numpy 2系向けにビルドされたscipyとABIが衝突するため |
| C-03 | ローカル(127.0.0.1)でのみ待ち受ける | 外部公開を意図しない |
| C-04 | ポートは8766 | カラオケアプリ(8765)との同時起動を可能にするため |

### 5.2 権利上の制約

- 取得した音源および生成した譜面は**私的利用の範囲**に限る

- 本体のライセンスはMITとするが、上記のような依存ライブラリごとの条件は別途従う

## 6. 受け入れ基準

| ID | 基準 | 確認方法 |
|---|---|---|
| A-01 | YouTube URLから譜面が生成される | 実際の楽曲で確認 |
| A-02 | 弦・フレットから元の音高が復元できる | 自動テスト |
| A-03 | 同時発音で同じ弦が重複しない | 自動テスト |
| A-04 | MusicXMLの各小節の音価合計が拍子と一致する | 自動テスト |
| A-05 | MusicXMLがMuseScoreで開ける | 手動確認 |
| A-06 | MIDIが書き出し→読み込みで一致する | 自動テスト |
| A-07 | 単音パートの音高が8割以上一致する | 自動テスト(合成音源) |
| A-08 | キック・スネアの検出率が7割以上 | 自動テスト(合成音源) |
| A-09 | エンジンが未導入でも起動し処理が完走する | 自動テスト |
| A-10 | 設定変更が保存され次回の採譜に反映される | 自動テスト |

## 付録A: 対応チューニング

**ギター**: レギュラー / 半音下げ / 全音下げ / ドロップD / DADGAD
**ベース**: レギュラー / 半音下げ / ドロップD / 5弦

## 付録B: 用語

| 用語 | 意味 |
|---|---|
| ステム | 音源分離によって取り出された、楽器ごとの音声 |
| ダウンビート | 小節の1拍目 |
| 量子化 | 演奏の揺れを含む発音時刻を、譜面上の格子(16分音符など)に丸めること |
| ポリフォニー | 同時に複数の音が鳴っている状態 |
| SDR | Signal-to-Distortion Ratio。音源分離の品質指標 |
